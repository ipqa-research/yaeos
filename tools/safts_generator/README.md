# SAFTs Generator Documentation

This directory contains the `fypp` source code and the bash script required to
generate the derivatives of SAFT equations of state (non-associative terms)
using `Tapenade` via the `yaeos` Tapenade API.

The generator relies on the `fypp` preprocessor to select which equation terms
are included in the Helmholtz free energy calculation for the desired SAFT
model. To use it, you must have the `fypp` preprocessor installed in your
environment and the `Tapenade` executable available in your `PATH`.

## Overview

The main purpose of this generator is to streamline the implementation of new
SAFT equations of state (EoS) when the modification only affects a single
contribution (or a few) to the Helmholtz free energy. 

Instead of rewriting the entire model for the Tapenade API, you can select the
existing terms already implemented in the [code](./code) subfolder and insert
the new contribution in its respective place. This new term can then be
conditionally included by the `fypp` preprocessor by specifying its
corresponding selection variable.

## Core Templates

In the root of the `safts_generator` directory, you will find the three main
templates for the code generator:

* **[`template.fypp`](./template.fypp)**: The main template for the code
  generator. This file contains the type definition of the SAFT model to be
  generated, along with its specific implementation of the Helmholtz free
  energy.

* **[`template_setup.fypp`](./template_setup.fypp)**: This template contains
  the model initialization code used to set up the SAFT model with the system's
  parameters.

* **[`template_get_v0.fypp`](./template_get_v0.fypp)**: This template contains
  the function to initialize the volume calculation, allowing you to choose an
  alternative strategy if needed.

These templates are not intended to be modified directly. Instead, they serve
as the foundation for the code generation process, which produces the final
Fortran source files required by `Tapenade`. However, you can inspect them to
understand how the code is structured and assembled into the final template.

These templates are kept separate because `Tapenade` interferes with the
`setup` and `get_v0` functions, altering their structures unintentionally.

To work around this, the generation workflow follows these steps:
1. `Tapenade` is invoked exclusively over the source code generated from
   `template.fypp`.
3. The clean `setup` and `get_v0` functions are injected back into the final
   `Tapenade` output using `sed` commands.

### Hardcoded Code Blocks

In the [`template.fypp`](./template.fypp) file, you will find several
predefined variables and code blocks that are available for use when
implementing new model terms. These setups are simple but critical. **Do not
modify or reimplement these blocks**, and ensure you use these existing
variables directly within your custom code blocks.

```fortran
integer :: i, j, k
```

These integer variables are already declared in the main template for your loop
iterations. You can use them directly in your code blocks without declaring
them again.

```fortran
! Residual Helmholtz free energy calculation
x = n / sum(n)  ! Mole fractions
n_tot = sum(n)  ! Total moles
nc = size(n)    ! Number of components

m_average = 0.0_8
do i = 1, nc
    m_average = m_average + x(i)*m(i) ! Segment average
end do
```

This code block is executed automatically in the main template before your
custom terms are evaluated. Avoid redeclaring or recalculating these variables
(`x`, `n_tot`, `nc`, and `m_average`) within your own code blocks to prevent
compilation errors or redundant computations.

## Bash Script

In the root directory, you will find the main execution script:

`generate_tape_safts.sh`

All command calls are handled inside this script. If you want to include a new
SAFT model generation and derivative computation, you can add another call to
the `generate_model` function. The script includes the `PCSAFT` model
generation as an example, which you can use as a template for your own
implementation.

To generate all the models defined in the script, simply run it in your
terminal:

```bash
./generate_tape_safts.sh
```

### Utility flags

The script also provides utility flags to facilitate the generation and
inspection process:

- Clean call:

```bash
./generate_tape_safts.sh --clean
```

This command erases all folders and files generated by the script, allowing you
to start fresh. When this flag is used, no `Tapenade` inputs are created and no
differentiation is performed.

- Skip differentiation:

```bash
./generate_tape_safts.sh --nodiff
```

By using the `--nodiff` flag, the script will generate the `Tapenade` input
files for all defined models but will skip the actual Tapenade differentiation
step. This is useful for quickly inspecting and verifying your generated source
code without waiting for the differentiation process to run for every model.

All the behavior of the script is documented in the actual script with
comments.

### Selection variables

The SAFT models are assembled using different terms and contributions. These
terms can be selected by modifying specific variables. Each variable selects a
different code block in the files of the [code](./code) folder, which are then
assembled together to create the final source code for the model. To create a
new code block, you can simply add a new selection string in the respective
`if-else` fypp statements.

 Let's examine the
`PCSAFT` generation call to understand how each variable is used:

```bash
model_name="TPCSAFT"
attributes="PCSAFT-ATTRIBUTES"
diameter="PCSAFT-DIAMETER"
zetas="PCSAFT-ZETAS"
ar_hard_sphere="Boublik-Mansoori-Carnahan-Starling"
ar_chain="Chapman-PCSAFT"
ar_dispersion="Dispersion-PCSAFT"
get_v0="PCSAFT_V0"

generate_model \
    "$model_name" \
    "$attributes" \
    "$diameter" \
    "$zetas" \
    "$ar_hard_sphere" \
    "$ar_chain" \
    "$ar_dispersion" \
    "$get_v0"
```

To generate a new model you should copy and paste this example and change the
variables defined. The `generate_model` function call should not be modified.
Each variable selects a different code block of each file in the [code](./code)
folder. Let's check each one separately:

* **`model_name`**: This variable defines the name of the model to be
  generated. It sets the name of the model's `type`, modifies the setup
  function name, and defines the model's module name. Additionally, the final
  files generated by the script are named using this variable. You should use
  uppercase letters here; the script automatically converts them to lowercase
  for file names and module names where necessary.

* **`attributes`**: This variable selects the code block that defines the
  model's attributes. It is also used to select the specific code for the
  model's setup function signature and body. The file affected by this variable
  is [`attributes.fypp`](./code/attributes.fypp). Both
  [`template.fypp`](./template.fypp) and
  [`template_setup.fypp`](./template_setup.fypp) are affected by this variable.
  Refer to these files for additional information regarding attributes and
  setup function definitions.

* **`diameter`**: This variable selects the code block that defines the
  molecular diameter calculation for the SAFT model. The file affected by this
  variable is [`diameter.fypp`](./code/diameter.fypp). Refer to that file for
  additional information regarding the diameter calculation and its
  implementation.

* **`zetas`**: This variable selects the code block that defines the SAFT zeta
  calculations ($\zeta_n$). The file affected by this variable is
  [`zetas.fypp`](./code/zetas.fypp). Refer to that file for additional
  information regarding the zeta calculations and their implementation.

* **`ar_hard_sphere`**: This variable selects the code block that defines the
  hard-sphere contribution to the Helmholtz free energy. The file affected by
  this variable is [`ar_hard_sphere.fypp`](./code/ar_hard_sphere.fypp). Refer
  to that file for additional information regarding the hard-sphere
  contribution and its implementation.

* **`ar_chain`**: This variable selects the code block that defines the chain
  contribution to the Helmholtz free energy. The file affected by this variable
  is [`ar_chain.fypp`](./code/ar_chain.fypp). Refer to that file for additional
  information regarding the chain contribution and its implementation.

* **`ar_dispersion`**: This variable selects the code block that defines the
  dispersion contribution to the Helmholtz free energy. The file affected by
  this variable is [`ar_dispersion.fypp`](./code/ar_dispersion.fypp). Refer to
  that file for additional information regarding the dispersion contribution
  and its implementation.

* **`get_v0`**: This variable selects the code block that defines the function
  to initialize the volume calculation. The file affected by this variable is
  [`get_v0.fypp`](./code/get_v0.fypp). This option only affects the
  [`template_get_v0.fypp`](./template_get_v0.fypp) file, as the
  [`template.fypp`](./template.fypp) file does not include a default `get_v0`
  function. Refer to these file for additional information regarding the volume
  initialization and its implementation.
